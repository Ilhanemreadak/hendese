Hendese · Components

DialogA single decision that stops the flow.

<dialog class="dialog"> is the look of the native modal window: a double frame like a stamp, with square corners. Opening and closing come from command / commandfor; the focus trap, Esc and the top layer come from the browser. In browsers that don't know these features, the package wires up the buttons.

Classes
.dialog · .dialog-head · .dialog-foot
Open / close
command="show-modal" · command="close" · commandfor · <form method="dialog"> · Esc
Result
dialog.returnValue · the close event
JS
Not required; the old-browser fallback lives in Hendese.init()

01

Anatomy

The header row has the title on the left and a close button on the right; the body in the middle; the decisions at the bottom. The dialog is linked to its title with aria-labelledby. The opening button calls the dialog by name with commandfor.

Example · release rollback

Roll web-api back to the previous release?

web-api in prod returns to the v4.8.1 image. Replicas are replaced one by one; it takes about 3 minutes with no downtime.
dialog.dialog
The native element. Opened with showModal(), it rises to the top layer, ::backdrop covers what's behind it, and page scrolling stops.
.dialog-head
The title (h2) and an optional close button. The title's id is the dialog's aria-labelledby value.
.dialog-foot
The decision buttons, aligned right. Usually the <form method="dialog"> element itself; the button's value becomes the return value.
command · commandfor
show-modal on the opening button, close on the closing button; commandfor is the dialog's id. No script is written.

02

Return value

A button inside form method=dialog closes the dialog and writes its value to dialog.returnValue. The page reads that value on the close event. Esc and the close button write no value.

Example · picking a maintenance window

When should report-cron be updated?

During the update, scheduled reports wait 10 minutes. No reports are waiting in the night window.

No choice yet. Open the dialog; close it with a button, with Esc or with the close button.

The old value stays

Esc and command="close" don't change returnValue; the value from the previous open stays in place. Clear it after reading it. Giving the “Cancel” button an empty value has the same effect: an empty value means “no decision”.

03

Confirm by typing the name

For an action that can't be undone, the reader confirms by typing what they are deleting. The match check is native form validation: required and pattern. If the name doesn't match, the form isn't submitted and .field shows the error line.

Example · deleting a service

Permanently delete search-indexer?

The service, its 3 replicas and the search-indexer-data volume are deleted. Search won't respond until the index is rebuilt. This can't be undone.

Type exactly search-indexer.

The name doesn't match.

Service in place: search-indexer · 3 replicas.

The “Cancel” button carries formnovalidate; otherwise, cancelling with an empty field would also trip validation. On open, autofocus puts focus on the field. The page script resets the form on close, so the field is empty again on the next open.

05

States

A dialog is closed or open; while it is open, the rest of the page is inert. Focus enters the dialog on open and returns to the opening button on close.

Example · where focus returns

Rotate the deploy-bot key?

The old key stays valid for 24 more hours; pipelines must switch to the new key in that time.

Open the dialog and close it with Esc; this line says where focus went back to.

StateHow it's setWhat happens

A dialog has no disabled state of its own. If the action can't be done right now, the opening button is disabled (disabled, or aria-disabled to give the reason); the dialog doesn't open just to say “can't be done”.

06

Do / don't

A dialog stops the reader. That is justified only for a single decision the reader must make now; not for giving information.

Do · one decision, verb label

Purge invoice-queue?

The 1,240 messages in the queue are deleted; unprocessed invoices aren't regenerated.
Don't · a dialog for information, four equal buttons

Info

Build #4182 was queued.
  • The title asks a question and names the object (“Purge invoice-queue?”), not “Info” or “Are you sure?”.
  • One decision, two buttons. Cancel, and a verb that says the outcome. If a third option is needed (the maintenance window above), all of them answer the same question.
  • Information that doesn't stop the flow (“was queued”) stays on the page: a .readout line or the status of the related row.
  • Never open a dialog from a dialog. If a second decision is needed, the first one closes.

07

API

The package gives the dialog only its look. All the behavior comes from the native element and the Invoker Commands feature; in browsers that don't know that feature, Hendese.init() wires up the buttons.

ItemValueNote
commandshow-modal · close · request-closeOn the button. show (non-modal) isn't used; the package's dialog is modal.
commandforthe dialog's idThe button can be outside or inside the dialog.
form[method="dialog"]—Closes the dialog on submit; the submitting button's value becomes returnValue. Validation runs; use formnovalidate to skip it.
close eventdialog.returnValueOn every close; read the result here, then clear it.
cancel event—Before closing with Esc; preventDefault() stops the close (for an unsaved-changes warning).
Old-browser fallback

If the browser doesn't know commandfor (no HTMLButtonElement.prototype.commandForElement), Hendese.init() attaches a click listener to every button[commandfor]: show-modal → showModal() (ignored if the dialog is already open), close → close(), request-close → requestClose() (close() if the browser lacks it; the cancel event fires only in the former). Like the native behavior, the fallback also copies the close button's value into returnValue; still, the most robust way to write decisions that need a return value is with buttons inside <form method="dialog">.
