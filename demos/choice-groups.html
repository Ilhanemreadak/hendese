Choice groupsNative radios, two looks.

.choice draws the native radio buttons inside a <fieldset> as chips or segments. The behavior belongs to the browser: keyboard, form submission and screen reader support come for free. The result of a choice is usually written to a .readout line.

Classes
.choice · .choice.is-seg · legend · small
Input
<input type="radio">; type="checkbox" for multiple choice
JS
Not required; a change listener to write the result

01

Variants

In the chip look, the selected item gets a heavy frame; in the segment look, a fill. Add small inside the label for secondary information.

Example · chip and segment
Region
Log level

Chips read well when the options are themselves names or values (region, environment, service). Segments feel more natural when you pick a position on a scale (level, range, size). Both use the same markup; the only difference is the .is-seg class.

No disabled look

The package defines no separate look for disabled; a disabled option looks the same as the others. Remove an unavailable option from the list and give the reason on a line near the group.

05

Do / don't

A few short options go in a segment; many or long options go in chips or a list. Always name the group with a legend.

Do · named group, short options
Cache TTL
Don't · unnamed group, long options
Choose
Accessibility

A screen reader announces the group by its legend text; the legend should be visible and say what is being chosen (“Cache TTL”, not “Choose”). Each group's name is unique on the page. Give the result line aria-live="polite" so changes made with the arrow keys are read too.
