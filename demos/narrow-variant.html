Hendese · Motion

Narrow variantSame sheet, second drawing.

When a dense drawing gets cramped in a narrow figure column, make a narrow drawing of the same sheet instead of shrinking it. The package ships the pattern: --naw/--nah on .drawing, two SVGs (.is-wide, .is-nar) and --nx/--ny/--nw on labels. When the fig container drops below 575px, the second drawing takes over; the engine rereads the drawing size on every measure.

Container
fig: .f-map · .fig-sheet · .sticky-fig · threshold 575px
Drawing
--aw/--ah wide, --naw/--nah narrow · .is-wide / .is-nar
Label
--x/--y/--w wide, --nx/--ny/--nw narrow
JS
api.aw / api.ah give the computed value on every measure

01

Problem and pattern

A wide drawing shrinks with contain in a narrow column, and its labels become unreadable. The fix isn't shrinking but redrawing the same information in a vertical layout.

In a live sticky scene, the figure column is a little more than half the window, and the drawing fits into it with contain logic. At 1100px that column drops below 500px; a horizontal drawing of 900 × 420 units falls to half its size. The package pattern has four parts and makes the page write no CSS:

  1. .f-map, .fig-sheet and .sticky-fig are a container named fig.
  2. .drawing carries the wide size in --aw/--ah and the narrow size in --naw/--nah. When the container drops below 575px, --aw/--ah switch to the narrow values; aspect-ratio and --u follow on their own.
  3. The drawing has two SVGs as direct children: .is-wide and .is-nar. .is-nar is hidden by default; in a narrow container they swap.
  4. HTML labels (.dl, .sl) carry --nx/--ny/--nw; in a narrow container the position is computed from these, and any value left out falls back to the wide one.
Both values at once

If .is-nar is present, --naw and --nah are required: if one is missing, --aw becomes invalid in a narrow container and the drawing loses its size. The SVGs must be direct children of .drawing.

02

Live example · cross-region failover

Region A goes down, the DNS record is switched to Region B, and B becomes primary. If the figure column is wider than 575px you see the horizontal drawing; if narrower, a vertical drawing of the same scene.

In live mode the figure column stays below 575px up to a window width of about 1350px; in that range the scene shows the vertical drawing, and Hoca moves to the narrow drawing's coordinates. In a wider window the horizontal drawing returns. With motion off, the figure is full width, so on desktop you see the horizontal drawing in its finished state.

Fig. 1. The heavy line is the region traffic goes to; the dashed line is the standby path. The dashed line between the regions is data replication.

  1. Normal operation

    The DNS record points to Region A. Region B waits as a standby that continuously replicates A's data.

  2. Region A goes down

    The health check in A fails three times in a row. Users start getting errors.

  3. DNS switches to B

    The record is pointed to Region B. Because the TTL is 60 seconds, every client sees the new address within a minute at most.

  4. B becomes primary

    Region B takes all the traffic. When A is repaired, it returns as the standby this time; replication runs in the opposite direction.

03

Coordinates and Hoca

When the container changes, so does the drawing unit. Pick Hoca's coordinates from the value the scene is measuring at that moment.

On every measure(), the scene reads the computed --aw/--ah of .drawing. The api.aw/api.ah passed to render and the aw/ah fields of the object stickyScene returns give the same value; in a narrow container it is 600 × 780. Hoca's coordinates are converted to percentages with this size too. still is used only with motion off; in that mode the desktop figure is wide, so it holds the wide drawing's coordinates.

04

With motion off

The narrow variant doesn't depend on motion: it looks only at the width of the fig container. With motion off, too, the narrow drawing shows when the container is narrow.

With reduced motion and below 1100px, .sticky is a single column and the figure is full width. On desktop the figure is wider than 575px, so the horizontal drawing shows in its finished state; on a phone the figure narrows and the vertical drawing comes in on its own. That way a reader on a narrow screen sees a readable vertical drawing, not a shrunken horizontal one.

Hoca's still copy (still) is placed with the wide drawing's coordinates. The container query works without JS as well: CSS alone decides which drawing shows.

05

Do / don't

The narrow drawing carries the same information; only the layout changes.

Do · same elements, new layout

Four boxes, four lines, five labels; the narrow drawing has them all, only their positions changed. The state classes (.dv-A, .dv-toB) keep the same names in both SVGs, so render stays a single code path.

Don't · drop information when narrow

Removing the replication line or the TTL label from the narrow drawing because there's “no room” tells the reader in the narrow column a different story.

Do · the aw the scene measured

var at = api.aw < 700 ? NARROW : WIDE;

Don't · window width or data-aw

innerWidth gives the window, not the column width, and misses changes like .sticky--dense. data-aw is only the initial value; it knows nothing about the container query.

06

API

The whole pattern lives in the package: three containers, two classes, five variables. The page supplies only the second drawing and the coordinates.

MemberWhat it does
fig containercontainer: fig / inline-size on .f-map, .fig-sheet and .sticky-fig. You can make your own wrapper a container with the same name. Threshold 575px.
--naw, --nahThe narrow drawing's unit, on .drawing. In a narrow container it overrides --aw/--ah (!important, so it can beat the inline value).
.is-wide, .is-narTwo SVGs, direct children of .drawing. .is-nar is hidden by default; in a narrow container they swap.
--nx, --ny, --nwPosition and width of .dl and .sl labels in the narrow drawing (in drawing units). A value left out falls back to the wide one.
api.aw, api.ahUpdated in live mode on every measure() via getComputedStyle(.drawing); --naw/--nah in a narrow container. The same in pin, sticky and fig scenes.
.sticky--denseAn alternative or addition: widens the figure column at 1100–1279px.
