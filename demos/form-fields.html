Form fieldsLabel, hint, error; native controls.

.field gathers a label, a native control (input, textarea, select) and the hint and error lines below it into a single column. The required mark comes from the :required attribute, and the error look from aria-invalid or the browser's own validation; no script is needed.

Classes
.field · .field-help · .field-error · .field-unit · .field-row · .mono
State
required · aria-invalid="true" · :user-invalid · disabled
String tokens
--str-required · --str-error
JS
Not needed; if present, it links the error text to aria-describedby only while the field is invalid

01

Structure

Label on top, control in the middle, hint and error below. Controls are styled only inside .field; other inputs on the page are left alone.

The label is tied to the control with for; the hint and error with aria-describedby. The border color lives in the --c variable: --ink-3 by default (3:1 contrast for non-text elements), --bad while the field is invalid. A multi-line field can be resized vertically.

02

States

Required, invalid and disabled. The error text sits in the HTML from the start; CSS shows it only while the field is invalid.

The “Error:” at the start of the error text comes from CSS (--str-error); color alone carries no meaning, so the state is also stated in words. That is why you write the text in the HTML in lowercase, as a continuation of the prefix.

A field has no “success” state, and .field does not accept the .s-* classes: a valid field stays plain. A green-bordered “correct” field makes the reader confirm every field one by one and loses the real error in the crowd.

03

Technical values, units, side-by-side fields

Values read character by character, like IDs, addresses and patterns, are set monospaced with .mono; a unit sticks to the right of the box with .field-unit. .field-row lays fields out side by side based on column width; in a narrow column they stack.

The unit sits outside the box, in a separate span: the value is just the number, so the form submits 3000, not 3000ms. The unit span's id is added to aria-describedby so the screen reader also says what the number measures. The required mark goes on the label even when the input is wrapped.

Each column is at least 200px (full width if the column is narrower); a field that does not fit moves to the next row. On fields that use .mono, also set spellcheck="false" and autocomplete="off", so the spell checker does not underline an ARN in red.

05

Translating the strings

“ · required” and “Error:” are CSS content strings; they do not appear in the HTML. A page with lang="tr" gets the Turkish strings automatically; for any other language, override two tokens.

The value is a CSS string, written with its quotes. The leading space and separator of the required text are part of the token too. The prefix is visible on screen only; for a screen reader the error text is the sentence in the HTML, so that sentence must make sense on its own.

06

Do / don't

The label is always visible; a placeholder does not replace it. An error is stated in a sentence, not by its color.

Do · a visible label
Don't · placeholder only

A placeholder disappears once you start typing; the reader has to remember what they are filling in, and its contrast is low. Shrinking the label and moving it inside the field has the same problem.

Do · an error sentence

Include the unit: Mi or Gi.

the unit is missing; did you mean 512Mi?

Don't · a red border only
Accessibility

aria-describedby points to the hint first, then the error: aria-describedby="x-h x-e". The screen reader reads the description in that order; the rule comes first, the violation second. A hidden element linked with aria-describedby is still read, so the package script removes the error ID from the list while the field is valid and adds it back at the end when the field becomes invalid (aria-invalid="true" or :user-invalid). Write both in the HTML; without JS the error text is always read, so the sentence should state the rule too. Set required with the required attribute: it draws the mark and makes the screen reader say “required”. For an error returned by the server, set aria-invalid="true" and move focus to the first invalid field.
