01

Anatomy

A pin scene has four layers: a long track, a sticky scene, a sheet and a drawing. The longer the track, the slower the scroll progresses.

The outer container .pin spans the page width and, in live mode, grows to --track (default 300vh). The .route-stage inside it sticks to the screen and stays 100vh tall, so the sheet holds still while you scroll along the track and only the drawing changes. The engine takes p from 0 to 1 between the start and end of the track and calls render(p, api) on every frame.

Live example · DNS resolution

A domain name query passes four stops and comes back with an answer. As you scroll, the ink advances, the HUD names the stage and Hoca carries the query.

The track is 280vh. In the first seventy percent the query travels from the client to the authoritative server; in the last part the green return line brings the answer back and the record is written to the resolver's cache. With motion off, the sheet below shows this finished state.

Why a CSS variable

The ink is drawn with stroke-dashoffset: calc(1 - var(--dns-go,1)). When JS writes nothing, the variable does not exist, the fallback is 1 and the line is complete. When live mode turns off, the engine removes every variable on .route-stage; you do not need a separate reset.

03

Variation · short track, no HUD or Hoca

Only the track and render are required in a pin scene. A three-step schema migration needs just 200vh; no HUD slot in the side column, no Hoca on the scene.

Expand, migrate, contract: new columns are added, data is copied in the background, and the old column is dropped last. The bar fills with the --mg variable; in live mode the old column's label first reads “in use” and turns to “dropped” on the last step. Because no still is given, this scene shows no Hoca copy under reduced motion.

04

With motion off

Reduced motion, widths under 1100px, print and a page without JS all see the same thing: the markup itself, which is the finished sheet.

With live mode off, .pin does not grow, .route-stage does not stick, and the sheet sits in the flow like a figure. Every item in the .beats list is visible; below 1100px the side column drops under the drawing. So the whole narrative must also live in the step text.

On leaving live mode (when the window narrows or the system setting changes), the engine clears .is-live with setLive(false), the classes added with api.cls and the variables written with api.set, then calls reset(api) if you gave one. reset is only for what you wrote by hand (for example, if you set a style directly on an element).

05

Do / don't

A pin scene holds the reader for a while; use it for a single narrative that earns it, and write its finished state into the markup.

Do · finished state by default

query

answer

The drawing is complete even without JS: var(--k,1), and intermediate states only under .is-live.

Don't · a sheet that starts empty

Defaults like .ps-go{stroke-dashoffset:1} leave an empty box under reduced motion, in print and on narrow screens.

Do · measure inside measure

Call getBoundingClientRect() once inside measure(api); render only writes api.cls, api.set and its return value.

Don't · read layout inside render

render runs on every frame; reading offsetWidth or getBoundingClientRect() there forces a layout recalculation every frame and makes scrolling stutter.

Beat count

Five or more steps are too many for one sheet: even if the side column folds the titles to one line, the reader misses what changed. Split the narrative in two, or switch to a sticky narrative.

06

API

Register between Hendese.init() and Hendese.start(). If the selector is not found, pinScene returns null and the page stays as it is.

MemberWhat it does
elThe scene's selector (the .pin element). It must contain a .route-stage and a .drawing.
chapThe HUD title; added to the hud object as the chap field.
stillHoca's still copy under reduced motion: {x, y, pose, face, bubble, bubbleUp, tag}, in drawing units.
render(p, api)On every frame; p is the smoothed track progress, 0..1. Returns {hud?, tb?, hoca?}; tb 0..1 turns the readout into a title block (.hud-tb).
measure(api)On re-measure (resize, font load). The one place to read layout.
reset(api)When live mode turns off, after the engine has cleared what it wrote itself.
apiel, stage, drawing, aw, ah (aw/ah are read from the computed --aw/--ah on every measure), set(k, v) (writes --k to .route-stage), cls(node, c, on), live(), poke(), seg, ease, lerp, clamp01.
hud returnFree-form fields: each key is written to the element with the same data-hud value; fill 0..1 scales the bar.
hoca return{x, y, pose, face, bubble, bubbleUp, tag, squash}; x, y is the bottom center of the feet, in drawing units.
