Intro

Hendese · Components

TabsAlternatives of the same thing, in one place.

.tabs[data-tabs] stacks interchangeable versions of the same content (format, environment, tool) and shows one at a time. Tabs are real <button> elements; ARIA roles, arrow keys and a roving tabindex come with the package. Without JS, or in print, all panels read one after another.

Classes
.tabs · [data-tabs] · .tab-h
Structure
role="tablist" · role="tab" + aria-controls · role="tabpanel" + aria-labelledby
State
aria-selected (set by the package) · hidden (set by the package)
Event
hendese:tab · detail.id
JS
Hendese.init() wires up tabs automatically

01

Anatomy

A tab strip on top, one panel per tab below it. A tab points to its panel with aria-controls, and a panel points to its tab with aria-labelledby. The package hides unselected panels; never write hidden on a panel in HTML.

Example · the same setting, three formats

YAML

JSON

HCL

.tabs[data-tabs]
The container. data-tabs marks where the package hooks in; .tabs gives the look.
[role="tablist"]
The tab strip. Its aria-label says what is being chosen (“Config format”). It scrolls sideways if it does not fit.
[role="tab"]
A <button type="button"> with a unique id and an aria-controls holding the panel's id. Put aria-selected="true" on the one selected at first; otherwise the first tab is selected.
[role="tabpanel"]
Linked to its tab with aria-labelledby, and keyboard-focusable with tabindex="0".
.tab-h
The panel's first element, a heading with the tab's name. Visually hidden on screen when JS runs; visible without JS and in print (see section 4).

02

Keyboard

The strip is a single Tab stop: Tab enters the selected tab, and the next Tab moves to the panel. Arrow keys move between tabs and also change the selection.

KeyWhat happens
TabEnters the selected tab; leaves the strip for the panel. Unselected tabs carry tabindex="-1" (roving tabindex).
→ · ←Selects and focuses the next or previous tab; wraps from the end to the start and back.
Home · EndSelects the first or last tab.
Enter · SpaceNot needed, since focus is already on the selected tab; works like a click.

Because the panel itself is focusable, keyboard users reach it and screen readers read its content even when it holds nothing focusable. If the panel already contains a focusable element (such as a scrollable code block), the panel's tabindex is still harmless.

03

Event and listener

Every selection fires a bubbling hendese:tab event on the container; detail.id is the selected tab's id. The initial selection on load fires no event.

Example · selection → readout

kubectl

helm

kustomize

Selected tool: kubectl. Pick another tab.

Because the event bubbles, one listener can watch several tab groups; a page that wants to remember the selection (localStorage, the address bar) does it in this event. The package does not store the selection.

04

Without JS and in print

Finished state: if JS does not run, the tab strip is hidden and all panels show one after another. In print the strip is not printed either and hidden panels open; no option is lost on paper.

ModeStripPanelsPanel heading
JS, screenVisibleOnly the selected panel; the others are hiddenVisually hidden; read by screen readers
No JSHidden (html:not(.js))All, one after anotherVisible
PrintHiddenAll, one after another; a hidden panel prints tooVisible
Every panel starts with its own heading

Without the strip, the reader can tell which option a panel is only from inside the panel. So each panel's first element is an <h3 class="tab-h"> heading with the tab's name. When JS runs it is visually hidden on screen (the strip already says the same thing); without JS and in print it shows as a small uppercase heading. Every example on this page is written this way; try it in print preview.

Do not write hidden on panels in HTML: if JS does not arrive, those panels never show. Hiding is the package's job alone (STANDARD.md §5: JS may only hide). Pick the heading level for the page; if the section heading is h2, use h3.

Why there is no disabled tab

A disabled tab says an option exists but not why it will not open; the keyboard also skips it. If the option does not exist in this context, do not draw the tab at all. If the option exists but is still empty, leave the tab enabled and say why in the panel, with .empty: “no deployments in the dr environment yet”.

07

Do / don't

Tabs are interchangeable versions of the same thing; the reader looks at only one. Steps done in order do not go in tabs.

Do · the same command, three package managers

apt

sudo apt install jq

dnf

sudo dnf install jq

brew

brew install jq

Don't · sequential steps in tabs

1 · build

make build

2 · test

make test

3 · release

make release

Number of tabs

Two to five tabs read well. More than that scroll in the strip and the reader cannot see the options; a <select> or separate sections work better then. A tab name is a short name, not a sentence.
