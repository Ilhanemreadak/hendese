A <button type="button"> with a unique id and an aria-controls holding the panel's id. Put aria-selected="true" on the one selected at first; otherwise the first tab is selected.

Linked to its tab with aria-labelledby, and keyboard-focusable with tabindex="0".

The panel's first element, a heading with the tab's name. Visually hidden on screen when JS runs; visible without JS and in print (see section 4).

Every panel starts with its own heading

Without the strip, the reader can tell which option a panel is only from inside the panel. So each panel's first element is an <h3 class="tab-h"> heading with the tab's name. When JS runs it is visually hidden on screen (the strip already says the same thing); without JS and in print it shows as a small uppercase heading. Every example on this page is written this way; try it in print preview.

Do not write hidden on panels in HTML: if JS does not arrive, those panels never show. Hiding is the package's job alone (STANDARD.md §5: JS may only hide). Pick the heading level for the page; if the section heading is h2, use h3.

Why there is no disabled tab

A disabled tab says an option exists but not why it will not open; the keyboard also skips it. If the option does not exist in this context, do not draw the tab at all. If the option exists but is still empty, leave the tab enabled and say why in the panel, with .empty: “no deployments in the dr environment yet”.

Number of tabs

Two to five tabs read well. More than that scroll in the strip and the reader cannot see the options; a <select> or separate sections work better then. A tab name is a short name, not a sentence.
