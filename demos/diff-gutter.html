Diff gutterMarks changed lines without polluting the copy.

The diff gutter marks the changed lines of a code block with Δ markers in the left margin. The markers live outside the <code> element, so when the reader copies the block they get no plus, minus or marker. A .diff-key in the text repeats the same marker and ties the explanation to the line.

Classes
.diff-src · .diff-gut · .diff-key · .plus · .minus
Attributes
style="--l:N" (line number, starting at 1) · data-m (marker text)
JS
Not needed

01

Anatomy

Three layers: .diff-src wrapping the code block, the .diff-gut strip inside it (hidden from screen readers), and one i element per changed line. The line number is set with --l, the marker text with data-m.

Example · a single change

The read timeout went from 60 to 120 seconds because the report endpoint is slow (line 5).

ElementWhereJob
.diff-srcInside figure.code, wrapping the preOpens a 40px strip on the left and pushes the code in
.diff-gutFirst child of .diff-srcHolds the markers; aria-hidden="true", not selectable
<i style="--l:N">Inside .diff-gutPaints line N with a green rule and a light background
data-mOn i and .diff-keyThe short marker printed in the strip and in the text
.diff-keyIn the explanatory textRepeats the same marker, framed

02

Kinds of change

The same structure describes any change. If a change spans several lines, give the first line the marker and the rest an empty data-m; the strip looks continuous.

Example · dependency upgrade

The database driver went from 8.11 to 8.13; it brings the fix for the connection pool leak. A security patch in the HTTP client.

Example · database migration, multi-line change

New due date column. A partial index covering only unpaid invoices (lines 4–6).

Line height

A marker's position is computed as 14px + (N − 1) × 1.6em, so it depends on the pre font size (--fs-sm, 12.5px) and the 1.6 line height. If you change the block's font size, the markers drift.

03

Key in the text

diff-key ties the explanation to the line. It works the same way in a paragraph, a change list or a definition list.

Example · change list
  • The memory limit went from 4 GB to 6 GB.
  • Eviction policy is LFU instead of LRU: frequently read keys stay.
  • Dead connections are detected within 60 seconds.

Summary. +3 changed lines, −0 deleted lines.

Example · in a definition list
Memory
4 GB → 6 GB
Policy
allkeys-lru → allkeys-lfu

04

States

The strip has a single state: changed. There is no separate color for added, deleted or risky lines; the kind of difference is stated in the text.

Example · changed, continued and unchanged lines

Minimum replicas went from 2 to 3. Scale-down behavior added (lines 4–5). Deleted line: targetCPUUtilizationPercentage: 80; scaling decisions now use the default CPU target.

Summary. +3 added or changed lines, −1 deleted line.

StateMarkupAppearance
Changed<i style="--l:N" data-m="Δ1">Green rule, light background, marker
Change continuesdata-m=""Rule and background, no marker
Unchangedno markerPlain code
Deletednot in the strip; the old value and a .minus count in the text—

A deleted line is no longer in the code, so the strip cannot show it; the package offers no marker for it. Write the old value in the explanation. Do not add inline colors to fake a red or yellow strip: readers take any color other than green to mean something, and a screen reader hears none of them.

05

Narrow space

The strip sits outside the pre, so when a long line scrolls horizontally the markers stay put; only the code scrolls.

06

Do / don't

Copied text is working text. Do not add characters inside the code to mark a change.

Do · marker in the strip
Don't · plus and minus inside the code
Accessibility

The strip and .diff-key are hidden from screen readers. So the explanation must describe the change on its own: what the value was, what it became, and the line if needed. The marker is only a shortcut for sighted readers.
