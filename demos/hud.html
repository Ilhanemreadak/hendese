Intro

Hendese · Motion

HUDOne fixed readout.

A page has a single #hud. In live mode, the most visible of the scenes that return hud pulls the readout into its own .hud-slot and fills in its fields. With motion off the readout never shows, so every piece of information in it is also written in the text.

Markup
#hud.hud · .hud-live · .hud-h · .hud-r · .hud-bar > #hud-fill · [data-hud]
Slot
.hud-slot inside the scene (pin: .f-side, sticky: .sf-head)
JS
The scene's render returns {hud: {…}}; there is no separate API

01

Anatomy

A header row, four field rows and a progress bar. The labels are fixed in the markup; the scene writes the values.

Figure 1. A still copy of the readout (on this page only, for explanation). The real readout is position: fixed, 260 × 176 px, and shows only under html.motion.

The readout is written once, at the end of the page. Each [data-hud] element shows the field of the same name in the hud object the scene returns; names are free-form. chap comes from the chap value in the scene registration, and fill (0..1) is not text but the bar's scale.

Six rows

.hud-live is a grid of six equal rows: header, four fields, bar. Do not change the number of fields; with less information, leave a row as —.

An error rate crosses a threshold, the primary on-call is paged, and with no answer it moves to the secondary. The HUD shows who is responsible at every moment.

03

Handover · a second scene

A page can have a second scene that wants the HUD. On every frame the most visible scene wins; at the handover the readout fades out of one slot and appears in the other.

In a sticky narrative the slot is inside .sf-head. The readout uses the same four labels, so choose fields general enough to fit both scenes: stage, source, owner, elapsed. As a scene nears the edge of the screen the readout's opacity drops; while reading between two scenes, there may briefly be no readout at all.

Figure 3. A backup is complete once it has left where it was taken and been verified in another region.

  1. Take a snapshot

    At 02:00 a consistent snapshot of orders-db is taken: 185 GB.

  2. Compress

    The snapshot is compressed down to 61 GB. This is the longest part of the job, about 18 minutes.

  3. Copy to a remote region

    The compressed file is written to storage in a second region; a backup kept in one region is useless if that region is lost.

  4. Verify

    The remote copy's checksum is compared with the source. Total time is 31 minutes; the job succeeded.

04

With motion off

Reduced motion, widths under 1100px, print and no JS: the readout never shows. This is not a gap; it is the contract.

.hud is display: none by default; it becomes the fixed readout only under html.motion. .hud-slot takes no space outside live mode either, so no gap is left in the side column. Everything the readout shows in the two scenes above (stage, owner, elapsed time) also appears in the step text: “The secondary on-call acknowledged at minute 9”, “Total time is 31 minutes”.

The readout is aria-hidden="true"; screen readers never read it. The text carries the same information in live mode too.

In the example on the right the sentence is cut off, three fields never change and the bar does not move: the readout takes space but says nothing. Keep values under 20 characters; anything longer is cut with an ellipsis.

Information only in the readout

A value that is in the readout but not in the text is lost for anyone using reduced motion, reading on a narrow screen or printing the page.

06

API

The HUD has no call of its own: Hendese.init() finds the readout, and the scenes' render return value fills it.

MemberWhat it does
#hud.hudOne per page. Looked up in Hendese.init(); without it, the HUD does not run at all.
[data-hud="name"]The element that receives the value of hud.name (textContent). It is not rewritten unless the value changes.
#hud-fillThe bar, scaled with scaleX by hud.fill (0..1).
.hud-slotWhere the readout docks inside the scene; its position and width are measured in measure.
render → {hud}In pin and sticky scenes. The fig scene does not request the HUD.
render → {tb}0..1: the readout's transition into a title block (.hud-tb); 1 is a full title block, 0 the live fields. Read in pin and sticky scenes.
cfg.chapAdded as hud.chap (if the scene gives chap inside hud, that wins).
