Intro

Hendese · Components

RunbookCheck, count, remember.

.runbook lists the items of a job carried out by hand: the counter, progress bar, reset and done line come with the package. The boxes are real <input type="checkbox"> elements; if you want, the choices are saved in the browser.

Classes
.runbook · .rb-head · .rb-count · .rb-bar · .rb-reset · .rb-list · .rb-item · .rb-done
Storage
data-store → localStorage key
Event
hendese:runbook · detail.done, detail.total
JS
Hendese.init() wires up the lists on its own

01

Anatomy

Counter, bar and reset at the top; the items in the middle; at the bottom, a done line that opens only when everything is checked. The choices in this example are saved in this browser.

Example · pre-release check
0 / 5
Ready to release.
.runbook
The container. With data-store, the choices are written to localStorage under that key.
.rb-count
The package rewrites the n / total text on every change; the initial value shows only without JS.
.rb-bar > i
The progress bar; the package sets its width as a percentage. It is decoration, so aria-hidden.
.rb-reset
Optional. Clears all boxes, updates the saved state and moves focus to the first box.
.rb-item
Inside a <label>: the hidden box, the drawn .box and the text .txt. The whole row is clickable.
.rb-done
Hidden; opens with .runbook.complete once every item is checked.

02

States

Empty, partial and complete. The state is computed from the checked boxes; the package adds the complete class, not the page.

Example · three states side by side
0 / 3
Alarm ready.
2 / 4
Cutover done.
3 / 3
Cache is warm.

These three lists have no data-store: they aren't saved, and their initial state comes from the checked attribute in the HTML. The reset button is optional too; you can drop it from short lists that run only once.

Initial state of a saved list

A list with data-store reads its saved state on load. If nothing is saved, the checked marks in the HTML are the initial state; after the first change, the saved state wins.

03

Event and listener

On every change, the list dispatches a bubbling hendese:runbook event on itself. The readout below listens to it and writes the next step.

Example · incident response, live readout
0 / 5
Response complete.

No response yet.

The first event fires on load, during Hendese.init(); the page script attaches its listener after that, so it must read the initial state itself. The readout's class changes with the state too: .bad with no items checked, .ok with all of them.

05

Do / don't

Each item is a single action, and you can verify it was done. A vague or compound item doesn't say what happened, even when checked.

Do · single action, verifiable
0 / 3
Service healthy.
Don't · vague and compound items
0 / 2
Done.
Key name

The data-store value is used as is. Giving two lists the same key writes one list's state over the other; pick a name that is unique per page, like app-page-list.

06

Accessibility and API

The boxes are native checkboxes; keyboard, screen reader and form behavior come from the browser.

ItemValueNote
data-storetextThe localStorage key; without it, the list isn't saved.
hendese:runbook{done, total}Once on load and on every change; bubbles.
.completeclassAdded to the list while every box is checked; .rb-done shows.
.rb-resetbuttonClears the boxes, saves, gives focus to the first box.
Accessibility

Tab moves from box to box, Space checks; the focus ring shows on the drawn .box. The aria-live="polite" on .rb-count reads out counter changes. The struck-through text is visual only; the state is read from the box itself.
