Hendese · Components

Variable registerA step's state at that moment.

.register shows a process's variables at a given moment as name / value rows; the row that changes in this step is highlighted with .now. It suits a pipeline's environment variables, a migration's lock state or the fields of a DNS query.

Classes
.register · .register-h · dl > div · div.now
Structure
<div><dt><dd> rows inside a <dl>
JS
Not needed; the page script changes the values and the .now class

01

Anatomy

The header row has the register's name on the left and position info on the right; name / value rows sit below. The name column widens to fit the longest name.

.register-h
The header row: <b> is the register's name (uppercase, drawing color), <span> the step or time.
dl > div
One row. Its dt is the name and dd the value; rows share one grid, so values start aligned.
div.now
The row that changes in this step; it gets a highlight fill and its name darkens. The fill comes in with a soft transition.

02

A pipeline's environment variables fill in as the job advances. Use the button to move to the next step; changed rows are highlighted, and the readout says what happened.

A long value breaks anywhere; the register never overflows its container. For a value not yet assigned, write a dash instead of leaving it blank: the row's presence says it will fill in at a later step.

Accessibility

A <dl> gives screen readers name / value pairs correctly; a <div> wrapping each row is valid HTML. .now is only a visual highlight: if what changed matters, also say it as text in a .readout next to it, with aria-live.
