Intro

Hendese · Components

Dimension noteA short explanation that opens when you click next to a value.

.dim-tip is a short note that says why a number, a field or a column is what it is, like the dimension text on a drawing. It is a native popover element: it opens when you click the button and closes when you click outside or press Esc. If the browser supports it, it sits right above the button.

Classes
.dim-tip
Structure
<button popovertarget="…"> followed directly by <div|span popover id="…" class="dim-tip">
Position
With anchor positioning, above the button, or below it if there is no room; without it, in the middle of the screen
JS
Not needed

01

Anatomy

Two elements: the button that opens it and the note. The button points at the note's id with popovertarget; the note comes right after the button. Hovering opens nothing; the note opens only on click, tap or Enter.

Example · click it

search-indexer uses at most 512 MiB of memory The index shard is 380 MiB; the rest is the batch write buffer.

button[popovertarget]
The button that opens it. If it has only an icon, write its aria-label as a question (“Why 512 MiB?”). The browser sets the button's aria-expanded state itself.
.dim-tip[popover]
The note. A <span> inside a paragraph, a <div> elsewhere. One short sentence or one calculation; mono, small size. Its edges use the drawing color like a dimension line; the top edge uses the pencil color.
Order
In the DOM the note comes right after the button, so screen readers and tab order find the note next to its button. Do not collect notes at the end of the page.

02

In running text

Right after a value in body text. The sentence is complete and correct without opening the note; the note only answers “why”.

Example · release note paragraph

With this release billing-worker pulls 25 messages from the queue at a time The queue returns at most 25 messages per request; a larger batch means two requests. and the visibility timeout went up to 90 seconds The slowest invoice takes 60 s; a 1.5× margin was added.. Old workers pick up the new setting on their next restart.

03

Next to a field heading

A note in the heading of a form group that explains what the options mean. The button sits inside the legend; the note comes right after it.

Example · deployment strategy
Deployment strategy
Rolling: replicas are replaced one by one, and the old and new versions run side by side for a few minutes. Blue / green: the new version is set up alongside, and traffic switches over at once.

For a single text field, do not put the button inside the <label>: a second control inside a label is invalid and muddles the label's click. Put the note in the group heading (legend) or in the field's help line. What the field expects (unit, format) goes in the .field-help line, not in a note.

04

Next to a table header

How a column is calculated is explained in its header, next to the column name. The note sits inside the header cell, after the button.

05

Position

If the browser supports CSS anchor positioning, the note is tied to its button and opens right above it; if there is no room above, it flips below. If not, the popover default applies: the middle of the screen.

BrowserWhere the note goesWhy
Has anchor positioningAbove the button; below it if there is no roomposition-area: block-start · position-try-fallbacks: flip-block; popovertarget makes the button an implicit anchor
Does notIn the middle of the screenThe browser's popover default (inset: 0; margin: auto); the note is still readable and closes the same ways

06

States

The note is closed or open. Opening takes one action; there are three ways to close it, and all of them come from the browser.

Example · open both in turn
Target group 3 / 3 healthy
/healthz every 10 s; 2 successes in a row count as healthy, 3 failures as unhealthy.
· response time p95 180 ms
95% of requests are faster than this; last 5 minutes.
StateHowWhat happens
ClosedDefaultThe note is not drawn; the button reads aria-expanded="false".
OpenClick, Enter or Space on the button; selector :popover-openThe note is in the top layer; the button reads aria-expanded="true". Focus stays on the button.
Light dismissClick outside · Esc · press the same button againThe note closes and focus stays on the button. If another note opens, the open one closes by itself; only one note is open at a time.
Focus:focus-visibleA focus ring on the button.

The note has no disabled state. If there is nothing to say, do not draw the button.

07

Do / don't

The note is extra information: readers must be able to decide correctly without ever opening it. Do not write tooltips that open on hover.

Do · the warning in the text, the detail in the note

A deleted volume cannot be recovered. The last snapshot was taken 6 hours ago Every day at 03:00 and 15:00; kept for 7 days.

Don't · the key information in the note, a tooltip on hover

The volume will be deleted Cannot be undone; no snapshot.

  • The key information is in the text. If something that changes the decision, like “cannot be undone”, appears only in a note, most readers never see it.
  • No tooltip on hover. title and hover tips are often invisible on touch screens, with a keyboard and under a screen magnifier. The package's note opens only on click.
  • The button label is a question (“Why 512 MiB?”), not “Info”; a screen reader user knows what it explains without opening the note.
  • The note comes right after its button. Use <span popover> inside a paragraph; collecting all notes at the end of the page breaks the reading order.
  • The note is short. One or two sentences or one calculation. If it is longer, move it into the text or a callout.
