Hendese · Hoca

Hoca · behaviorWho speaks, where he walks.

Scenes only request Hoca; on every frame the controller decides who owns him. With no request, Hoca goes back to his home on the rail. Between two nearby points he walks; if they are far apart he fades out and appears at the new spot, so he never crosses unrelated content.

01

Controller

The module that draws Hoca only draws what it is told; the controller decides who speaks. The rules are short and fixed.

SituationWhat happens
No scene requests himHe stays idle at his #hoca-home on the rail.
The active section is data-hoca="quiet"Hoca at home drops to 45% opacity, and the rail box fades too (.rail.hoca-quiet). It does not block scene requests.
Several scenes request himThe first scene in registration order wins.
Owner changed, the two points ≤ 260 px apartHe walks for 650 ms (walkA/B, facing the direction of travel); the speech bubble and tag are hidden while walking.
To or from home, > 260 px, part navigation320 ms: he fades out at the old spot and appears at the new one.
Same scene, new coordinatesThe controller does not interpolate; smooth movement is the scene's job (in a pin scene p is already smoothed).
Reduced motion (desktop)No movement: each scene's still value is placed in the drawing as a still copy.
< 1100px, printHidden.

02

Live example · handover

Two figures side by side. Choose which one wants Hoca. Handover happens between scenes: he walks to a nearby point, fades out and in for a distant one, and jumps within the same scene.

Requesting Hoca

The left figure is requesting. Hoca is next to the queue, with his clipboard.

260 px

The threshold is in viewport pixels, not drawing units. At 1440px wide the two distances are about 170 px (walk) and 480 px (fade); in a narrower window the distances shrink.

03

Quiet section and dismissal

This section carries data-hoca=quiet: while you read it, Hoca stays faint at home. If the reader wants Hoca gone entirely, scenes stop requesting him.

When section tracking finds the active section, it checks for data-hoca="quiet": if present, Hoca at home drops to 45% opacity and the rail's Hoca box fades. It suits places where Hoca has nothing to say, such as long reference tables, API sections and rules. If a scene in this section requests him, he still speaks; quiet only affects how he stands at home.

Hendese.hoca.dismiss() sets the shared dismissed flag and wakes the loop. Scenes read the flag and return hoca: null; the two figures above are written this way. Hoca stays at home. To undo it, set Hendese.hoca.dismissed = false.

On. Scenes can request Hoca.

Not persistent

The flag lives only while this page is open; when the page reloads, Hoca comes back. To make it persistent, store the preference yourself and set Hendese.hoca.dismissed = true before Hendese.start().

04

With motion off

Under reduced motion Hoca does not walk or fade, and there is no home: a still copy stands in the drawing of every scene that requests him.

When live mode turns off, the engine hides the fixed layer and puts a copy inside the drawing for every scene that has a still (left/top are converted from drawing units to percentages). If still is a function, it is read again on every Hendese.refresh() call; if it returns null, that scene gets no copy. That is why the choice and dismissal buttons above call refresh() on every change (in live mode the call does not interrupt a handover): under reduced motion, too, Hoca moves to the chosen figure and disappears when dismissed.

Below 1100px and in print the copies are hidden too. Since Hoca carries no information in any mode, nothing is lost.

05

Do / don't

Hoca accompanies a scene; he is not run between sections to draw attention.

Do · one point per scene

Each scene asks for Hoca at a single, empty spot: at the edge of the drawing, not on top of an important label. A short walk between nearby scenes looks natural.

Don't · a new spot every frame

If a fig scene changes the coordinates every frame, Hoca jumps; the controller does not interpolate within the same scene. If you need continuous movement, use a pin scene.

Do · respect dismissal

render and still check Hendese.hoca.dismissed first and return null.

Don't · ignore the flag

A scene that does not read the flag keeps calling Hoca after the reader has dismissed him; the dismiss button looks broken.

06

API

The controller has no call of its own; Hendese.start() sets it up. Scenes make requests; the page manages only the flag and the still copies.

MemberWhat it does
#hoca-homeThe home on the rail. If it is missing and no scene has a still, Hoca is never created.
data-hoca="quiet"On a [data-section] element: while that section is active, Hoca at home is 45% opaque.
render → {hoca}{x, y, pose, face, bubble, bubbleUp, tag, squash, hidden}, in drawing units; null → no request. hidden: true keeps ownership but hides Hoca; when he shows again, he appears in place without walking.
stillAn object or a function; the still copy under reduced motion. null → no copy.
Hendese.refresh()Removes the still copies and places them again from the still values. In live mode it does not touch the handover state; a walk or fade in progress is not interrupted, so it can be called unconditionally on every state change.
Hendese.hoca.dismiss()dismissed = true and wakes the loop.
Hendese.hoca.dismissedA readable / writable shared flag; writing it also wakes the loop.
Hendese.lockTo(id)The part-navigation lock; while it holds, scene requests are ignored: Hoca fades to home, and when the lock ends he appears in the target scene.
