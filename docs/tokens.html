Hendese · Tokens

TokensThe single source for color, size, type and motion.

Every Hendese component reads its values from the CSS variables in tokens.css. This page is the full list of those variables: what they are for, their values in the light and dark themes, and how to override them.

01

Philosophy

Components never write a color, size or duration; they only read tokens. Re-theming means overriding a few variables in your own CSS.

One source, both themes on one line

Every color token is defined on one line with light-dark(light, dark). Because :root has color-scheme:light dark, the system theme is followed by default; there is no separate dark theme file and no duplicated selector block.

Layer order

The whole theme loads inside @layer. The order is fixed; a later layer overrides an earlier one. CSS you write outside any layer beats every layer, whatever its specificity, so overrides need neither !important nor long selectors.

Overriding

Link your own stylesheet after hendese.css and write only the tokens you want to change. Give both themes on the same line. One color re-themes everything: --draw, --accent-soft, --pencil, --pencil-2 and --scene-shade are derived from --accent with color-mix(). Set --accent-2 as well, for link text contrast:

The derived tokens resolve once, on :root. Overriding only --accent on a descendant does not change --draw or the pencil tones; in a local override, write the derived tokens too. Below, the left box overrides only --accent; the right one overrides it with its derived tokens.

Forcing a theme

Setting data-theme="light" or data-theme="dark" on <html> overrides the system preference. [data-theme-toggle] buttons change this attribute, store the choice in localStorage under the hendese-theme key and dispatch the hendese:theme event. To avoid a theme flash on load, inline the dist/head.js line in <head>.

Dark sheet: .scene-dark

.scene-dark only sets color-scheme:dark. Because light-dark() tokens resolve against the color scheme of the element that uses them, everything inside this container is drawn dark even in the light theme. The container must read its own background and text color again; an inherited color arrives already resolved on the parent.

Turkish uppercase

Under lang="tr", CSS text-transform:uppercase applies Turkish casing rules: i → İ, ı → I. That is right for Turkish words but breaks English technical words printed in uppercase (build → BUİLD). On a Turkish page, Hendese.init({englishStems:/build|deploy|image/i}) wraps the matching words of uppercase labels in <span lang="en">. Stems are project-specific; without them nothing happens. Explicit lang attributes always win. In the example, both labels are Turkish; only the second marks "build" as English.

String tokens

Some UI strings are printed with CSS content: the corner label of the selected station (--str-selected), the detail panel title (--str-station) and the form field prefixes --str-error and --str-required. They default to English; a page with <html lang="tr"> gets the Turkish set automatically through :root:lang(tr). For another language, override them the same way. JS-side strings work alike (English by default, Hendese.locales.tr on Turkish pages) and change with Hendese.init({strings:{…}}).

08

Contrast and forced colors

Two system settings change the tokens: a request for more contrast, and the Windows forced colors (high contrast) mode.

prefers-contrast: more

When the user asks for more contrast, four tokens are redefined: pencil lines turn to ink, and the strong edge and secondary text darken one step. Components read tokens, so no extra rule is needed.

forced-colors: active

In forced colors, the browser maps backgrounds and colors to the system palette, so meaning carried by background color alone is lost. That is why the package draws selected and current states (.choice selection, pressed .toggle-btn, the selected station, aria-current in .steps) with a frame in Highlight, and progress bars (.rb-bar, .hud-bar) and the checked checkbox with a Highlight fill. Disabled elements get GrayText. In your own components, don't tie meaning to the background alone either: add a border, a pattern or text.
