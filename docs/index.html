Intro

Hendese · Design language

HendeseA blueprint-style design language for pages that explain by measuring.

Hendese (Ottoman Turkish): geometry, the knowledge of measuring; the root of the Turkish word for "engineer". This package draws documentation, training and tool pages the way an engineer draws a sheet: pencil guides, inked figures, dimension lines and a title block.

01

Philosophy

Four rules. Every part of the package rests on one of them.

  1. The finished state is always correct

    HTML and CSS describe the finished drawing. Animation is only the way there: with motion off, on a narrow screen, in print or without JS, readers still get the complete figure.

  2. One line family

    Guide (pencil), drawing (ink), accent and dimension. Solid means real; dashed means example or limit. No shadows, gradients or glow.

  3. Meaning lives in the text

    Drawings are aria-hidden; whatever they show is also said in the text, the beat list or the caption.

  4. Small and predictable

    Tokens are the single source of truth, CSS sits in cascade layers (@layer), and JS is one loop that sleeps when idle. A build step is optional.

02

Installation

Three ways in. All three use the same dist/ files.

1. Copy the folder

Put the dist/ folder in your project (fonts come in dist/fonts/).

2. npm dependency (local folder or git)

3. Single-file page

To ship one offline HTML file, paste the contents of dist/hendese.inline.css (fonts embedded) and dist/hendese.js into the page as <style> and <script>, and put the icon sprite (dist/icons.svg) at the start of <body>.

Browser support
Current browsers from the last two years: light-dark(), :has(), container queries and @layer are required. The [data-reveal] scroll animation switches off gracefully where it is not supported.

04

Package layout

Source in src/, built output in dist/. The docs and the starter page ship in the same package.

LayerContents
hendese.tokensColor, font, size, motion and string tokens
hendese.baseReset, base typography, focus ring, reduced motion
hendese.layoutRail, top bar, rulers, canvas, section header, hero
hendese.componentsCode, callout, table, steps, runbook, choice groups, register, stamp, survey log
hendese.blueprintSheet, drawing units, labels, line families, title block, station explorer
hendese.motionPin/sticky scenes, HUD, intro, sketch, [data-reveal]
hendese.hoca, hendese.printMascot layer; print rules

Your own unlayered CSS overrides every layer. No need to fight specificity.

Accessibility contract

The package provides these; the page author does their share.

TopicPackagePage author
MotionUnder prefers-reduced-motion, all transitions stop and scenes rest in their finished statePuts their own transitions under html.motion
DrawingsSVGs and Hoca are aria-hiddenWrites the drawing's meaning into the text, a beat or the caption
KeyboardSkip link, focus ring, focus trap and Esc in the drawer, native radio groupsBuilds interaction from native elements (button, input)

LanguageEnglish UI strings by default, the Turkish set on Turkish pages; there, englishStems marks uppercase English words with lang="en"Sets the page language (lang) correctly
Codepre tabindex="0" scrolls, copy button; diff markers stay out of the copyWrites code blocks as figure.code
ContrastUnder prefers-contrast:more, pencil lines turn to ink; in forced colors, selection and progress are drawn with HighlightNever carries meaning by background color alone
Standard
The rules every part of the package follows (tokens, status, interaction states, container queries, finished state, accessibility, language) live in STANDARD.md in the repository. Tests enforce most of them: tests/unit/standard.test.mjs blocks raw values (color, font size, spacing, radius, duration, z-index) in component CSS and checks that every class is shown on a page; the e2e tests scan every page with axe in light and dark themes. All of it runs with npm test.

06

Versioning

SemVer. Any change to the documented contract (classes, tokens, data attributes, ids, events, storage keys, exports) is a major release.

ChangeRelease
Visual fix, bug fixpatch
New token, component, recipe, API memberminor
Rename, removal, change to the finished statemajor

Releases are cut with npm run release: build → test → CHANGELOG check → npm pack → zip → git tag. Release notes live in CHANGELOG.md.
