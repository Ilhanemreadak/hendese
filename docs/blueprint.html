Blueprint and recipesThe rules of the drawing language, and drawing recipes you can copy.

Every recipe has three parts: when to use it, a live drawing and markup you can copy. Drawings are built from the package classes; the few details the package does not cover live in a small style block with the .r- prefix. Recipes needed on more than one page (.tag, .cells, .needle, .lamp, and .stamp-k inside a drawing) are package classes; the style block only names them.

01

Language rules

One line family, mono labels and two line meanings: solid is real, dashed is a sample or a boundary.

Hendese drawings read like technical drawings. Every line and every label says something; there is no decoration. The weight family is fixed:

ClassNameExampleWhen
.ln-pencilguideGrid, baseline, dimension extension line, secondary leader.
.ln-drawdrawingBox, face, track: the body of the drawing. This is the default.
.ln-strongemphasisHighlights one thing in a drawing: the current moment, the selected track.
.dimdimensionDimension line and arrowheads; the value goes next to it with .dim-t.
.ln-draw .ln-dashsamplePattern, sample value or boundary: “something like this may exist”.
.ln-ghostghostA part that does not exist yet or is no longer used; a previous/next position.
.ln-blockblocked pathA path that was tried and rejected; always paired with a stop mark.
.ln-draw .ln-okstatus color.ln-ok / .ln-warn / .ln-bad only change the color; use them with the weight family.

Label rules

  • Labels are HTML positioned in drawing units, not SVG text (.dl): selectable, translatable, and they grow with the scale.
  • The heading line is mono, uppercase and widely tracked (a small-caps effect); the value line is plain mono.
  • Status is shown only with the .state label and the ok / warn / bad colors; color never carries meaning alone, there is always a word next to it.
  • No shadows, gradients or glow. Depth comes from isometric faces and the .fill-scene fill.
  • SVG is always aria-hidden="true"; the meaning also lives in the caption, the step list or the surrounding text.

Static finished-state rule
The default markup always draws the finished state: even if the animation never runs (reduced motion, print, no JavaScript), the picture is complete and correct. Motion only plays the path to that finished state; intermediate states are added with a class or a CSS variable. That is why the recipes on this page show only the finished state; the Motion engine page covers motion.

02

Sheet

The scene frame: title, steps in the side column, drawing in the middle, caption below. Static (unpinned) figures use the lighter fig-sheet.

.frame is a four-area grid: .f-head (chip and title), .f-side (the .beats step list or prose), .f-map (drawing) and .f-foot (caption, explorer panel). The fill and border come from the .frame-bg layer. Below 1100 pixels the side column drops below the drawing.

03

Drawing units

A drawing is designed in its own unit system and scales with the width of its container. SVG and HTML labels use the same coordinates.

  • On .drawing, --aw and --ah are the width and height of the drawing in units; the SVG inside uses the same system through viewBox="0 0 aw ah".
  • .dl labels are positioned in the same units with --x, --y, --w.
  • --u is one unit in pixels (100cqw / aw); write type and spacing as calc(12 * var(--u)) and give them a readable floor with max().
  • Lines keep the same weight at every scale through vector-effect: non-scaling-stroke.
  • The callout box is HTML; the leader line is drawn in SVG and ends at the box's left edge, level with the first line. So the line stays attached even when the box text grows.

05

Station explorer

Makes every stop on a line clickable; the description of the selected station appears below the sheet.

Give the container data-explorer="panel-id". The [data-key][aria-pressed] buttons inside it become the explorer; the panel switches between the [data-for="key"] blocks in the element with that id. Hover and focus preview a station, and leaving returns to the selected one; a click selects and fires a hendese:explore event (detail.key). Without JavaScript and in print, every block is visible; JS writes the .show class.

In one sentencePush → the build produces an image → the registry stores it → the cluster updates to the new image.

Source. The repository where the code lives. A push to the main branch fires the build trigger; other branches stop at the filter.
Build. A temporary container started fresh on every run. It builds, tags and pushes the image; it does not deploy.
Registry. The image repository. Tag format: prod-<8 hex>; this is the only contract between CI and CD.
Cluster. The deployment tool sees the new tag and updates the desired state; pods are replaced one by one.

06

Isometric box

Shows a closed unit (container, environment, package) with three faces: the front face is paper, the top and right faces are scene fill.

The front face is a W × H rectangle; the top and right faces are parallelograms of the same edges shifted by dx = +36, dy = −22. The label goes in the top left of the front face; corner ticks mark the face's frame.

Measuring tools

For measuring a value against a rule: the caliper shows the match character by character, the dial shows the gap between desired and actual.

The caliper measures a tag against a regular expression. Cell states: pass (green underline), fail (red box, marked ▲), missing (dashed red, empty), unchecked (dashed, faded). Cell width is in drawing units; the sliding jaw stops at the right edge of the last cell.

09

Fault lamp panel

Shows which phase of a process failed: a proportional phase strip, zone brackets and numbered lamps.

The middle section of the strip is proportional to time (10 units = 1 s) and reads against the seconds ruler below it; the side sections are not to scale and are set apart by zone brackets. Each lamp is a row of the list below; the lit lamp and its phase are drawn in red. The list is the text equivalent of the drawing.
